# v1 技术验证标准

> **版本**：v1.0-draft  
> **日期**：2026-08-06  
> **适用范围**：Go2（`192.0.2.61`）↔ 边侧 RTX 5070（`192.0.2.93`）**专网**下的视觉语言导航（VLN）与边端分离系统。  
> **配套**：`[v1-双路上行语义调度方案.md](./v1-双路上行语义调度方案.md)` · `[v1-仿真环境技术选型方案.md](./v1-仿真环境技术选型方案.md)` · `[v1-世界模型-VLN-VLA选型方案.md](./v1-世界模型-VLN-VLA选型方案.md)` · **`[v1-motion体系对齐说明.md](./v1-motion体系对齐说明.md)`**（motion / motion_ws / Go2 四仓对照）

## 1. 验证目标（一句话）

在 **专网** 上稳定运行「L0 子图 + L1 RGB + L2 任务语义」双路上行 → 边侧 VLM/VLN 推理 → **SemanticDirective** 下行 → 端侧 BT 加权导航，以 **任务成功率** 与 **边端分离系统流畅性** 作为是否通过技术验证的判据。

---

## 2. 验证分级（Gate）

| Gate | 环境 | 核心判据 | 工具 |
|------|------|---------|------|
| **G0** | 本机回环 `127.0.0.1` | 协议 + 分层对齐 + 仿真 frontier@1 | `./scripts/run_sim_bench.sh` |
| **G1** | **专网** 协议联调 | 三通道连通、对齐率、无阻塞 | `config/edge.env` + 狗 uplink |
| **G2** | **专网** VLN 短任务 | 语言指令下 subgoal / frontier 语义命中 | 标准任务包（§5） |
| **G3** | **专网** VLN 完整任务 | **任务成功率 SR** ≥ 门槛 | 多轮重复 + 记录表 |
| **G4** | **专网** 长稳 | 边端流畅性 30 min 无退化 | 并发监控脚本 |

**通过 v1 技术验证**：至少 **G1 + G2 + G3（SR 达标）+ G4（流畅性达标）**；G0 为前置回归，不替代专网真机。

## 3. 专网环境标准（G1 前提）

### 3.1 网络拓扑

```
┌────────────────── 专网 192.0.2.0/24 ──────────────────┐
│  Go2 Orin NX          有线/5G CPE           边侧 5070        │
│  192.0.2.61  ◄────────────────────►  192.0.2.93   │
│       │ :9877 子图上行                          │            │
│       │ :9878 RGB 上行                          │ edge       │
│       │ :9879 directive 下行 ◄──────────────────┘            │
└─────────────────────────────────────────────────────────────┘
```

| 项 | 要求 |
|----|------|
| 网络类型 | **专网 / 实验局域网**，狗与边侧同网段可达 |
| 禁止项 | 验证记录不得仅使用 `127.0.0.1`（仿真用 `config/sim.env` 除外） |
| 边侧监听 | `LISTEN_HOST=0.0.0.0`（`config/edge.env`） |
| 狗端配置 | `edge_uplink.yaml` 中 `edge_host=192.0.2.93` |
| 端口 | 9877 子图 / 9878 RGB / 9879 directive；**边侧仅单实例** |
| 连通性 | 狗→边 `ping` RTT p50 < 10 ms；三端口 TCP 可连 |

### 3.2 专网基线（G1 通过条件）

| ID | 指标 | 通过阈值 | 采样 |
|----|------|---------|------|
| N1 | 子图上行到达率 | ≥ 99%（10 min） | 边侧 `[subgraph]` 计数 vs 狗端发送 |
| N2 | RGB 上行到达率 | ≥ 95%（10 min） | 允许 P 帧丢弃策略下丢帧 |
| N3 | L0/L1 对齐率 | ≥ 95% | 边侧 `[align] layers=` 日志 |
| N4 | Directive 下行到达率 | ≥ 99% | 狗端 `DIRECTIVE_ACCEPT` 计数 |
| N5 | 断网恢复 | 断网 30 s 后 60 s 内恢复 N1–N4 | 拔网线 / `iptables` 模拟 |
| N6 | 专网带宽占用 | 子图 + RGB 合计 < 10 Mbps 均值 | `iftop` / 边侧统计 |

## 4. 边端分离系统流畅性标准（G4 核心）

「流畅性」= **边侧推理与网络 I/O 不得拖垮端侧 Super-LIO + BT 控制闭环**。

### 4.1 端侧（狗）指标

| ID | 指标 | 通过阈值 | 说明 |
|----|------|---------|------|
| E1 | Super-LIO 控制频率 | 相对无上行基线下降 **< 5%** | 对比 `with_edge_uplink:=false` |
| E2 | BT planning 周期 | p95 增幅 **< 20%** | 语义注入后不得卡死 replan |
| E3 | 上行发送队列 | 无持续积压 > 5 s | 子图/RGB 有界队列 |
| E4 | Directive 处理 | 过期 directive **0 误用** | TTL 校验 |
| E5 | 急停/交还控制 | `stop_nav.sh` 10 s 内清栈 | 安全兜底 |

### 4.2 边侧（5070）指标

| ID | 指标 | 通过阈值 | 说明 |
|----|------|---------|------|
| S1 | 单次语义查询延迟 | p50 < 3 s，p95 < 5 s | 子图 tick → directive 发出 |
| S2 | 端到端延迟 | p50 < 4 s，p95 < 8 s | 含专网 RTT + 狗端接收 |
| S3 | 查询频率 | 0.2–1 Hz 可持续 | 不因 GPU OOM 崩溃 |
| S4 | 边侧 CPU/RAM | 子图+帧缓存 RAM < 1 GB | 不含模型权重 |
| S5 | 单实例 | 9877/9878 **仅一进程监听** | 避免 RGB timeout |
| S6 | 多模态就绪率 | L0+L1+L2 对齐 **≥ 90%** | 与 `multimodal_ready_rate` 同义 |

### 4.3 流畅性综合判定

**G4 通过**：连续 **30 min** 专网联调同时满足：

- E1–E4 全部达标  
- S1–S3、S5–S6 全部达标  
- 无 `[ERROR]` 级连续告警 > 1 min  
- 无狗端 `/cmd_vel` 抢占抖动（边侧不得直控）

## 5. 视觉语言导航（VLN）任务成功率标准（G2/G3 核心）

### 5.1 任务定义

v1 采用 **「语言指令 → 边侧语义 → BT frontier 选择 → 端侧几何执行」** 的 VLN，**不等同** Habitat VLN-CE 的离散 waypoint 成功率，但指标可对齐。

| 任务级别 | 描述 | 示例 |
|---------|------|------|
| **T1 语义选型** | 给定指令，边侧 directive 首选 frontier 正确 | 「找厨房」→ `fr_kitchen` |
| **T2 短程到达** | 单 subgoal：语义选对且机器人进入目标区域 | 距目标 < 1.0 m 且停留 ≥ 3 s |
| **T3 多 subgoal 任务** | 2–5 个 sequential subgoal 完成整链 | 走廊 → 厨房 → 返回 |
| **T4 长指令 RxR 风格** | 自然语言长描述（可选 G3+） | 多句路径描述 |

### 5.2 成功率指标

| 指标 | 公式 | v1 通过阈值（G3） |
|------|------|------------------|
| **SR_task** | 完成任务数 / 总任务数 | **≥ 70%**（T3，≥5 次独立试次） |
| **SR_subgoal** | 到达 subgoal 数 / 总 subgoal 数 | **≥ 80%** |
| **frontier@1** | directive 首选 frontier = GT | **≥ 75%**（T1，专网 20 tick） |
| **SPL_task**（可选） | SR × (最短路径 / 实际路径) | **≥ 60%**（需记录轨迹） |
| **语义增益** | frontier@1(VLM) − geom@1 | **> 0**（至少 1 个标准场景） |

**最低验收组合（G3）**：

```
SR_subgoal ≥ 80%  AND  frontier@1 ≥ 75%  AND  语义增益 > 0
```

### 5.3 标准任务包（专网 G2/G3）

| 任务 ID | 指令（L2） | GT frontier / 区域 | 层级 |
|---------|-----------|-------------------|------|
| VLN-01 | 「找厨房」 | `fr_kitchen` / 厨房门口 1 m | T1+T2 |
| VLN-02 | 「去走廊尽头」 | `fr_hall` | T2 |
| VLN-03 | 「探索未访问房间」 | 未访问 frontier 之一 | T1 |
| VLN-04 | 「先去厨房再去卧室」 | 序列 subgoal | T3 |
| VLN-05 | 几何陷阱场景 | GT=kitchen，geom 倾向 hall | T1（对照 geom） |

每个任务 **独立 session**，`session_id` 不同；每项 **≥ 3 次** 重复，取均值。

### 5.4 失败分类（须记录）

| 代码 | 含义 | 归因 |
|------|------|------|
| F_net | 专网断连 / RGB timeout | 网络 / 边侧多实例 |
| F_align | L0/L1 未对齐 | Aligner / 时钟 |
| F_sem | frontier@1 错误 | VLM/VLN 模型 |
| F_geom | 语义对但路径不可达 | 占据栅格 / planner |
| F_ctrl | 控制抖动 / recovery 循环 | BT / closed_loop |
| F_ttl | directive 过期未刷新 | 边侧频率 / TTL |

**技术验证报告须附失败分布**，SR 低于门槛时需说明主因（F_* 占比 > 40% 的项）。

## 6. 分阶段验证流程

### 6.1 G0 仿真回归（每次改协议必跑）

```bash
cd RGB_ws && ./scripts/run_sim_bench.sh
```

| 检查项 | 阈值 |
|--------|------|
| align_hit_rate | 100% |
| layer_fusion@1（corridor） | 100% |
| multimodal_ready_rate | 100% |

### 6.2 G1 专网协议联调

```bash
# 边侧（专网）
cd RGB_ws && ./scripts/run_edge_server.sh   # 使用 config/edge.env

# 狗端
AUTOSTART=false WITH_FOXGLOVE=false ./scripts/nav/start_demo_scan_nav.sh
# edge_uplink: with_edge_uplink:=true, edge_host:=192.0.2.93
```

记录 10 min：N1–N6、S5（`ss -lntp | grep 9877` 仅一行）。

### 6.3 G2 短任务 VLN

- 不发完整 mission 自动巡航（除非 T3 需要）  
- 手动或 BT 触发 **单 subgoal** + 语言指令  
- 验证 `DIRECTIVE_ACCEPT` + frontier 权重变化 + T2 到达

### 6.4 G3 任务成功率批测

- 任务包 VLN-01～05 各 ≥ 3 次  
- 汇总 SR_subgoal、frontier@1、语义增益  
- 边侧 scheduler：`qwen_vl`（主）或 `mock`（对照）

### 6.5 G4 长稳流畅性

- 30 min 连续：子图 1 Hz + RGB 15 fps（或 MSRGB 联调档）+ 周期语义查询  
- 并行采集：狗端 LIO 频率、边侧 S1/S2、网络 N1–N2

## 10. 未达标时的改进优先级

| 主失败码 | 优先动作 |
|---------|---------|
| F_net | 单实例 edge；`full_network` 启动；查防火墙 |
| F_align | 校 `subgraph_version`；增大对齐窗口 |
| F_sem | 换 Qwen-VL prompt；增 L2 task_context；对照 layer_fusion |
| F_geom | 端侧 planner / 占据；语义权重降 `w_graph` |
| F_ctrl | 禁边侧直控；查 closed_loop 抢占 |
| F_ttl | 提高查询频率或增大 `ttl_ms` |
