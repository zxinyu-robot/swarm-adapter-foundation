# v1 本机仿真环境 — 技术选型方案

> **版本**：v1.0-draft  
> **日期**：2026-08-06  
> **定位**：在 **本机 CPU** 上复现「子图 + RGB 双路上行 → 边侧调度 → SemanticDirective 下行」闭环，用于 **可用 / 可评估 / 可信 / 可靠** 四维对比后再上真狗。  
> **不替代**：Gazebo / Habitat 全物理仿真（**Gazebo 线见 `gazebo/` + [v1-Gazebo与Isaac仿真选型.md](./v1-Gazebo与Isaac仿真选型.md)**）；真狗 Super-LIO + BT（已在 `MotionSLAM_ws`）。

---

## 1. 为什么先做协议级仿真

| 维度 | 协议级仿真（本方案） | 全物理仿真 | 直接真狗 |
|------|---------------------|-----------|---------|
| **可用** | 纯 Python，无 GPU/ROS2 | 需 Isaac/Habitat + GPU | 需狗在线、场地 |
| **可评估** | 场景带 GT frontier，自动算命中率 | 可但搭建成本高 | 难重复、难 A/B |
| **可信** | 与真狗 **同一 MSRGB / 子图 JSON / Directive schema** | 传感器/动力学差异大 | 金标准但慢 |
| **可靠** | CI 可跑、回归固定 |  flaky 较多 | 受网络/电池影响 |

**结论**：v1 技术选型（mock vs 几何基线 vs **Qwen-VL** vs **StreamVLN** 支路）先在 `RGB_ws/sim/` 跑通 **边侧调度 + 对齐 + 指标**；真狗仅做最终验收。  
> **WM / WAM / VLN / VLA 全量对比**见 `[v1-世界模型-VLN-VLA选型方案.md](./v1-世界模型-VLN-VLA选型方案.md)`。

## 2. 仿真架构（多模态分层输入）

边侧调度器按 **L0 → L1 → L2** 分层消费输入；Aligner 以 `subgraph_version` 为 join_key 对齐三层后再调度。

```
┌──────────── sim/device_sim.py ────────────────────────────────┐
│  读 scenarios/*.json → 每 tick 生成 LayeredTick                  │
│  L0 structure  sparse_subgraph.v1 + multimodal_layers manifest │
│       └─ :9877  TCP JSON Lines                                  │
│  L1 vision     MSRGB (video360p) + rgb_tag                       │
│       └─ :9878  二进制帧                                         │
│  L2 task       task_context（挂载于 L0 子图扩展字段）              │
└────────────────────────────┬────────────────────────────────────┘
                             │
┌──────────── edge/server.py + aligner.py ──────────────────────┐
│  SubgraphReceiver + RgbReceiver → align_bundle()              │
│  layers_present / layers_aligned → 调度器 gating                 │
│  Scheduler: mock | geom_baseline | layer_fusion_stub | qwen_vl  │
└────────────────────────────┬────────────────────────────────────┘
                             │ SemanticDirective :9879
┌──────────── sim/directive_sink.py + eval_runner.py ───────────┐
│  收 directive → 对比 GT + geom@1 vs 分层融合@1 vs mock@1         │
└─────────────────────────────────────────────────────────────────┘
```

| 层 | ID | 载体 | 内容 |
|----|-----|------|------|
| **L0** | `structure` | `:9877` 子图 JSON | pose、frontier、拓扑、`geom_score` |
| **L1** | `vision` | `:9878` MSRGB | RGB 关键帧、`rgb_tag`（仿真标签 / 真狗 DDS） |
| **L2** | `task` | 子图 `task_context` | 自然语言指令、`goal_room_type` |

**join_key**：`{session_id, subgraph_version, timestamp_ns}`（见 `multimodal_layers.manifest()`）。

## 3. 可对比技术路线（选型矩阵）

| ID | 调度器 | 输入 | 输出 | 本机要求 | 评估指标 |
|----|--------|------|------|---------|---------|
| **S0** | `mock` | L0 子图 | 全 frontier 列表 | CPU | 连通性、延迟 |
| **S1** | `geom_baseline` | L0 子图 `geom_score` | top-1 frontier | CPU | geom@1 vs GT |
| **S1.5** | `layer_fusion_stub` | L0+L1+L2 对齐包 | top-1 frontier | CPU | 分层融合@1 vs geom@1 |
| **S2** | `qwen_vl` | L0+L1+L2 | SemanticDirective | GPU 12GB+ | frontier@1、置信度校准 |
| **S3** | `streamvln` | L1+L2 → 官方 `/eval_vln` | `action_bias` + frontier | CPU stub / GPU 5801 | vln_action@1、action_bias |

**v1 仿真默认跑 S0 + S1 + S1.5**（`layer_fusion_stub`）；**S3** 用官方协议 stub：

```bash
./scripts/run_sim_bench.sh --scheduler streamvln
# 真 GPU：先 ./scripts/run_server.sh，edge --scheduler streamvln --streamvln-url http://127.0.0.1:5801/eval_vln
```  
**模型族对照**（VLM/VLN/WAM/WM）：见 `[v1-世界模型-VLN-VLA选型方案.md](./v1-世界模型-VLN-VLA选型方案.md)` §6。

## 4. 场景与 Ground Truth

场景文件：`sim/scenarios/*.json`

```json
{
  "name": "corridor_3frontiers",
  "task": { "instruction": "找厨房", "goal_room_type": "kitchen" },
  "steps": [{
    "version": 1,
    "expected_frontier_id": "fr_kitchen",
    "frontiers": [{ "frontier_id": "fr_hall", "geom_score": 0.95 }, ...],
    "layers": {
      "vision": { "rgb_tag": "kitchen_door" },
      "task": { "goal_room_type": "kitchen" }
    }
  }]
}
```

**指标**（`sim/metrics.py`）：

- `frontier_top1_acc`（mock@1）：边侧 mock directive 首选 frontier 是否等于 GT
- `geom_baseline_acc`（geom@1）：仅 L0 几何 top-1 与 GT 一致比例
- `layer_fusion_acc`（分层融合@1）：L0+L1+L2 stub 与 GT 一致比例
- `multimodal_ready_rate`：三层均对齐就绪的 tick 比例
- `align_hit_rate`：RGB `subgraph_version` 与边侧对齐成功率
- `e2e_latency_ms`：子图 tick → directive 收到

## 5. 一键运行

```bash
cd RGB_ws
./scripts/run_sim_bench.sh                    # G0 全场景 + layer_fusion_stub + strict
./scripts/run_sim_bench.sh --scenario corridor_3frontiers
./scripts/run_sim_bench.sh --scheduler streamvln   # S3：官方 /eval_vln CPU stub
./scripts/run_sim_bench.sh --scheduler mock --no-strict
```

**G0 通过条件**（`sim/gates.py`，默认 `--scheduler layer_fusion_stub`）：

- 全场景 directive 收到率、schema 校验、三层就绪 = 100%
- `corridor_3frontiers`：directive@1 = 100%，且 fusion > geom（geom=0%）
- 未通过时 `run_sim_bench.sh` **exit 1**（可用 `--no-strict` 仅看报告）

报告输出：`sim/reports/<timestamp>/summary.json` + `summary.md`（含 G0 Gate 明细）

## 6. 与真狗联调关系

| 阶段 | 环境 | 目的 |
|------|------|------|
| **Phase Sim** | 本机 `run_sim_bench.sh` | 选型、回归、协议变更 |
| **Phase Mock Edge** | 本机 edge + 狗 DDS 上行 | 带宽/对齐/时序 |
| **Phase VLM** | 5070 + 真狗 | 语义质量验收 |

仿真通过 **不保证** 真狗 SLAM/占据栅格行为一致；仅保证 **边侧协议与调度逻辑** 可评估。  
**专网真机 VLN 与任务成功率门槛**见 `[v1-技术验证标准.md](./v1-技术验证标准.md)`。
