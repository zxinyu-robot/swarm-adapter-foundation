# RGB_ws 与 quadruped-crossfloor-nav-ws、legged-navigation-runtime 的耦合

## 定位

RGB_ws 是**边侧语义调度网关**，不是独立导航栈。它必须与两个端侧项目协同：

| 项目 | 角色 | 与 RGB_ws 的关系 |
| --- | --- | --- |
| [quadruped-crossfloor-nav-ws](https://github.com/zxinyu-robot/quadruped-crossfloor-nav-ws) | Go2 端侧导航执行栈 | **端边协同主链路**：端侧上行子图+RGB，边侧下行 SemanticDirective |
| [legged-navigation-runtime](https://github.com/zxinyu-robot/legged-navigation-runtime) | 定位失效恢复状态机 | **安全兜底**：定位丢失时优先于一切任务指令 |
| RGB_ws | 边侧语义调度 | 把视觉+结构对齐成任务级指令，不碰运动控制 |

## 一、端边协同拓扑（RGB_ws ↔ quadruped）

```text
Go2 端侧（quadruped-crossfloor-nav-ws）          边侧（RGB_ws）
┌──────────────────────────────┐        ┌────────────────────────────┐
│ Super-LIO / PCT / SCAN / BT  │        │ edge/server.py 网关         │
│                              │  :9877 │  收子图（frontiers/nodes）   │
│ edge_uplink ── 子图上行 ──────┼───────►│  (subgraph JSON)            │
│                              │  :9878 │  收 RGB（~30fps 缓存）       │
│ rgb_forward ── RGB 上行 ─────┼───────►│                            │
│                              │        │  语义调度（qwen_vl 等）      │
│ directive_receiver            │  :9879 │  SemanticDirective 下行     │
│   ◄── 指令下行 ───────────────┼────────│                            │
│   → BT 校验 → 规划 → 执行     │        │                            │
└──────────────────────────────┘        └────────────────────────────┘
```

**对齐字段**：

| 端侧（quadruped） | 边侧（RGB_ws） |
| --- | --- |
| `EDGE_HOST` 环境变量 | `GO2_HOST`（config/edge.env） |
| 子图上行端口 `:9877` | `SUBGRAPH_PORT=9877` |
| RGB 上行端口 `:9878` | `RGB_PORT=9878` |
| 指令接收端口 `:9879` | `GO2_DIRECTIVE_PORT=9879` |
| `WITH_EDGE_UPLINK=true` 开关 | `AUTO_DIRECTIVE=true` |

## 二、安全优先（RGB_ws ↔ legged-navigation-runtime）

两者**不直接通信**，通过端侧行为树（BT）的优先级协同：

```text
SemanticDirective（任务级，来自 RGB_ws）
        │
        ▼
    BT 校验前置条件：localization_healthy ?
        │
   ┌────┴────────────┐
   │ healthy         │ lost / degraded
   ▼                 ▼
执行任务指令      RecoveryPlugin 接管
                        │（legged-navigation-runtime）
                   Tracking→Searching→Aligning→Verifying→SafeStop
                        │
                   恢复后重新校验 → 回到任务指令
```

**规则**：
1. `RecoveryPlugin`（安全）永远优先于 `SemanticDirective`（任务）；
2. RGB_ws 的指令必须带 `map_version` 与 `ttl_ms`——定位恢复后若地图版本已变，旧指令作废；
3. RGB_ws 只产出 frontier 选择，不产出速度/关节指令，执行权始终在端侧 BT + 本地控制器。

## 三、SemanticDirective 的状态契约字段

RGB_ws 下行的指令携带以下字段，与 legged 的恢复语义对齐：

| 字段 | 含义 | 与恢复的耦合 |
| --- | --- | --- |
| `map_version` | 子图版本 | 定位重置后 map_version 变化 → 旧指令过期 |
| `issued_at_ns` / `ttl_ms` | 签发时间 / 有效期 | 超过 ttl 的指令端侧拒绝 |
| `confidence` | 调度置信度 | 低置信度 → 端侧可用几何兜底 |
| `candidate_frontier_ids` | 候选 frontier（含兜底） | 首选失效时端侧可用次选 |

## 四、边侧模型：Qwen2.5-VL-3B

默认调度器 `qwen_vl` 使用 **Qwen/Qwen2.5-VL-3B-Instruct**（原 7B 的轻量替代）：

- 与 7B 同架构（`Qwen2_5_VLForConditionalGeneration`），代码零改动；
- 4bit 量化显存约 2.5 GB，消费级 GPU 即可跑 demo；
- 无 GPU 时设 `QWEN_VL_STUB=true`，用 CPU 规则 stub 验证协议链路。

## 五、最小联调验证

```bash
# 1. 边侧（本机，无 GPU 协议自测）
cd RGB_ws
QWEN_VL_STUB=true ./scripts/run_edge_server.sh

# 2. 模拟上行（另一终端）
python3 scripts/mock_uplink_client.py

# 3. 与 Go2 真机联调
#    quadruped 侧：WITH_EDGE_UPLINK=true EDGE_HOST=<本机IP> ./scripts/nav/start_demo_scan_nav.sh
#    RGB_ws 侧：config/edge.env 中 GO2_HOST=<Go2 IP>
```
